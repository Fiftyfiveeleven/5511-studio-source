# Phase 2: review, reuse, edit and sync

## Use the new tools

**Features** works even before the first AI build. Save a blank project, open Features, review a pack, then save a version. Packs are real source and cost no OpenAI tokens. A Next.js pack adds `/studio-faq`, `/studio-calculator` or `/studio-tasks`; add links from your own navigation when ready. Its `studio.tests.json` requirement is added without removing prior requirements. The calculator has clearly labelled example pricing. The checklist stores personal data in that app's browser; it does not create a shared team database. An opaque HTML preview may prevent browser storage and shows that limitation.

Save a version as a blueprint to reuse its source. Cloud blueprints are private to your signed-in account, with RLS; guests use IndexedDB. Export a blueprint to share it with an employee, who can import and review it. Reuse preserves unrelated destination files and asks you to choose a version when both contain a different file. Full-stack and browser formats cannot be mixed into an existing project. Studio does not add settings credentials, but manually embedded secrets in source would remain part of that source: inspect code before sharing.

**Edit design** opens a source-backed inspector. Select static HTML or a native JSX element by clicking the preview or choosing from the source element list. Edit plain text, supported styles, links, or image URL/alt text. A draft can be undone/redone and saved as an immutable zero-token revision. Cloud saves compare the expected revision atomically; a concurrent change causes a conflict instead of an overwrite. Runtime instrumentation is applied only to the temporary Sandbox copy and is not committed/exported. Generated expressions, dynamic styles/spreads and component props are intentionally not rewritten. Next.js shows the saved runtime; after a draft change select further elements from the list, then save and relaunch. There is no automatic compile or paid preview launch on each keystroke.

**Design review** runs free DOM checks in the currently visible preview. Repeat for mobile and desktop. Checks cover overflow, a primary heading, labels, small targets, image loading, small text and approximate solid-background contrast. They are not a full accessibility audit and do not fully evaluate gradients, images behind text, responsive states or off-screen workflows. Reports come from the untrusted app and are advisory.

For an AI review, upload the current screenshot first; optionally add target reference screenshots second and third. This sends only the supplied images, project brief and current DOM observations to GPT-5.4-mini. It uses existing token and dollar limits, conservative image reservations, a maximum of 4,000 output tokens, exact-request caching and no automatic retries. Failed or uncertain attempts remain in Usage. Reviews do not edit the app. Choose findings to add a proposed change to chat, where the normal estimate/build review still applies. Download the report if you need to keep it; review-panel results are session state.

**GitHub sync** supports a dedicated repository previously published by the same Studio project. Credentials stay in the employee's HTTP-only browser cookie. The project stores only repository, branch and last synced commit. Pulling reads immutable commit trees and compares base, Studio and incoming files. Independent file changes merge; same-file divergent changes and edit/delete conflicts require a choice. Review shows both complete file versions. A merge saves a new Studio revision; SQL remains source for manual review, never automatically applied. A changed remote head or project revision stops saving/pushing. Remote changes that arrive after the final pull check will be caught before the next push. Push uses a normal commit and `force:false`, deletes only previously managed paths, and preserves unrelated files. Exported README, Vercel settings and ignore/env examples are created on first publish and left alone on subsequent pushes. Legacy project markers infer editable source paths for the first managed-file sync. GitHub protection rules can reject a push. No PR creation, arbitrary repository import, binary asset sync, or line-level conflict editor is included.

## Project files

Open **Files** beside Preview to browse the project's saved source by folder. Search filenames or enable **Search inside files** to search contents. Select a file to read, copy, download, or edit it. New file paths can include folders; Rename / move changes the path, and Delete removes an optional file. Update any imports or references after a move. Required entry files cannot be moved or deleted.

**Save version** (or Cmd/Ctrl+S in the source editor) validates the draft and saves an immutable revision through the same browser/cloud permissions and conflict checks as design edits. It uses no AI tokens. Discard restores the saved source. Unsaved edits block leaving the editor; refresh/close prompts the browser's unsaved-change warning. Viewer and example projects are read-only.

The browser manages supported text source files, not arbitrary binary uploads. Import text accepts UTF-8 files at the project root; use Rename / move to place them in supported folders. Existing app limits apply: 80 files, 160,000 characters per file, and 500,000 serialized source characters total. Empty folders are inferred from file paths and are not stored. The Database tab continues to show the separate SQL schema.

Validated: three file-operation tests, production build, and browser create/edit/save, content search, rename/save, delete/discard workflows on an isolated test project.
